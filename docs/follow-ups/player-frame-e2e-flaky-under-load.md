# 플레이어 프레임 추출 e2e가 병렬 부하에서 불안정하다

## 증상

`e2e/font-match.spec.ts`의 "영상에서 영역을 드래그하면 그 장면의 프레임이 잘려
크로퍼에 올라온다" 테스트가 전체 스위트를 병렬로 돌릴 때 첫 시도에서 종종
실패한다(재시도하면 통과, `1 flaky`). 단독 실행(`--workers=1`)이나 수동
Playwright 프로브에서는 안정적으로 통과한다.

## 원인 추정

이 스위트는 여러 스펙이 동시에 실제 yt-dlp·유튜브·무료 번역 API를 호출한다.
동시 호출이 겹치면 유튜브·번역 제공자가 일시적으로 rate limit(429)을 걸어
프레임 추출이 늦어지거나 실패한다. `docs/follow-ups/translate-provider-rate-limit.md`
와 같은 성질의 문제다.

## 지금 처리

`playwright.config.ts`에서 `workers: 2`, `retries: 1`로 완화했다. 흐름 자체는
단독 e2e와 수동 프로브(`arm → 드래그 → POST /videos/<id>/frame 200 → 잘린 JPEG가
크로퍼에 표시`)로 검증됨.

## 다음 단계

- 실제 영상·번역을 쓰는 e2e들을 한 그룹으로 묶어 순차 실행하거나,
- 프레임 추출 e2e를 라우트 레벨 테스트(`reference-db.spec.ts`의
  "영상 프레임 추출 요청은 지정한 영역의 JPEG를 돌려준다")만 남기고
  브라우저 드래그 통합 테스트는 수동 확인으로 둔다.
