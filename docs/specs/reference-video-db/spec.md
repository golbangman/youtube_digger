# 레퍼런스 영상 DB

## User-visible outcomes

- 홈 화면에서 URL 입력 폼 아래에 지금까지 참고한 영상 목록이 보인다.
- 유튜브 URL을 넣으면, 영어 자막이 있으면 번역까지 해서, 없으면 "자막 없음" 상태로, 그 영상이 목록에 등록되고 작업 페이지로 이동한다.
- 목록의 각 항목은 썸네일, 제목, 확보한 자산 아이콘(자막 번역·배경음악·영상), 메모를 보여준다.
- 각 항목의 메모를 자유롭게 적고 고칠 수 있다.
- 각 항목을 삭제할 수 있다. 삭제하면 그 영상의 레코드와 받아둔 MP3·MP4 파일이 함께 지워진다. 삭제 전 확인을 받는다.
- 항목을 누르면 그 영상의 작업 페이지(`/videos/[id]`)로 이동한다.

## Approved scope

- 홈 화면의 참고 영상 목록 UI(썸네일·제목·자산 아이콘·메모·삭제·항목 열기).
- URL 제출 시 레코드를 만드는 등록 흐름. 영어 자막이 있으면 기존처럼 번역해 저장하고, 없으면 자막 없이 등록한다.
- 자막이 없는 레코드의 작업 페이지: 자막 영역은 "자막 없음"을 알리고, 폰트 추천·배경음악·영상 다운로드 영역은 정상 동작한다.
- 항목별 메모 입력·수정.
- 항목 삭제: 레코드 + 그 영상의 `data/audio`·`data/video` 파일 제거, 삭제 전 확인.

## Observable acceptance criteria

- 홈 화면에 URL 폼과 그 아래 참고 영상 목록이 함께 보인다. 등록된 영상이 없으면 빈 상태 안내가 보인다.
- 영어 자막이 있는 URL을 제출하면: 그 영상이 목록에 나타나고, 작업 페이지에 영어·한국어 자막이 보이며, 자막 아이콘이 목록 항목에 표시된다.
- 영어 자막이 없는 URL을 제출하면: 그 영상이 목록에 나타나고, 작업 페이지의 자막 영역은 "자막 없음"을 알리며, 자막 아이콘은 표시되지 않는다. 폰트 추천·배경음악·영상 다운로드 영역은 그대로 쓸 수 있다.
- 배경음악(MP3) 또는 영상(MP4)을 받은 영상은 목록 항목에 해당 자산 아이콘이 표시된다. 아직 안 받았으면 그 아이콘은 없다.
- 목록 항목에 메모를 입력하면 저장되고, 홈 화면을 다시 열어도 그 메모가 남아 있다.
- 목록 항목의 삭제를 실행하면 확인을 물어보고, 확인하면 그 항목이 목록에서 사라지고 그 영상의 MP3·MP4 파일도 없어진다. 그 뒤 작업 페이지 주소로 다시 들어가면 없는 영상으로 처리된다.
- 목록의 항목을 누르면 그 영상의 작업 페이지로 이동한다.
- 이미 등록된 URL을 다시 제출하면, 새로 등록하지 않고 그 영상의 작업 페이지로 바로 이동한다.

## Settled constraints and rationale

- **레퍼런스 등록은 URL 제출 시점에 일어난다. 자막 번역은 되면 하는 부가 작업이다.** 사용자가 A안으로 확정. 한국어 영상처럼 영어 자막이 없는 레퍼런스도 목록에 넣고 배경음악·영상을 확보할 수 있어야 `PRODUCT.md`의 "URL 하나로 자산 확보 + 참고 이력" 약속이 성립한다.
- **삭제는 레코드와 그 영상으로 받아둔 MP3·MP4 파일까지 함께 지운다. 삭제 전 확인을 받는다.** 사용자가 A안으로 확정. "필요 없으면 지운다"는 의도에 맞고, 안 쓰는 미디어 파일이 남지 않는다. 파일까지 지우므로 실수 방지용 확인을 둔다.
- **폰트 추천에는 자산 아이콘이 없다.** 폰트 추천은 저장물 없이 외부 링크만 주는 도구라 "확보한 자산"으로 남는 게 없다. 아이콘 대상은 자막 번역·배경음악·영상 세 가지다.
- **목록은 홈 화면의 URL 폼 아래에 둔다.** `PRODUCT.md` 핵심 흐름이 "URL 붙여넣기 → ... → 나중에 목록에서 다시 열기"이고, URL 입력과 목록을 한 화면에 두면 그 흐름이 자연스럽다.

## Assumptions

- 썸네일은 유튜브 공개 썸네일 주소(`https://img.youtube.com/vi/<videoId>/...`)를 그대로 쓴다. 별도 저장이나 API 없이 브라우저가 불러온다.
- 목록 정렬은 최근 등록순이다. 검색·필터·태그는 이 기능에 넣지 않는다.
- 메모는 항목마다 여러 줄 입력이 가능하고, 입력란을 벗어날 때 저장된다.
- 영어 자막이 있는 URL을 제출하면 번역은 지금처럼 제출 처리 중에 이루어진다(길면 그만큼 기다린다). 없으면 번역 없이 곧바로 등록한다.
- 등록된 레코드에는 메모가 함께 저장되고, 자막 텍스트는 없을 수 있다.
- 목록 항목이나 작업 페이지에서 자막이 없던 영상에 나중에 자막을 다시 시도하는 경로는 이 기능에서 만들지 않는다. 처음 제출 때 없으면 없는 상태로 둔다.

## Off-limits and why

- 검색·필터·태그·폴더 분류 — 항목 수가 적은 초기 단계에는 최근순 나열로 충분. 이후 필요해지면 다룬다.
- 자막이 없던 영상에 나중에 자막을 다시 붙이는 재시도 UI — 이 기능 범위 밖. 처음 제출 때의 상태로 둔다.
- 목록을 다른 기기·브라우저와 동기화 — `PRODUCT.md` 경계(로컬 단일 사용자).
- 여러 항목 일괄 삭제·일괄 다운로드 — 로컬 단일 사용자, 항목 수가 적음. 범위 밖.
- 메모의 서식(마크다운·리치 텍스트) — 평문으로 충분.
- 삭제한 항목 복구(휴지통) — 확인 단계로 충분. 범위 밖.

## Deferred points

- 목록의 정렬·검색 방식 고도화 — 항목이 많아지면 다룬다. 앞선 스펙들에서도 미뤄둔 항목이다.
- 보관한 MP3·MP4의 자동 정리(오래된 파일) — 삭제로 개별 정리는 되지만, 전체 용량 관리는 별도 과제로 남긴다.

## Remaining risks

- 유튜브 썸네일 주소는 유튜브 쪽 정책 변경으로 형식이 바뀌거나 특정 해상도가 없을 수 있다. 대체 해상도나 빈 자리 처리가 필요할 수 있다.
- 등록 시점을 URL 제출로 옮기면서, 영어 자막이 있는 영상은 번역이 끝날 때까지 제출 처리가 길어진다. 긴 영상에서 사용자가 기다리는 시간이 늘 수 있다(기존 자막 기능과 같은 성질).
- 삭제가 레코드와 미디어 파일을 함께 지우므로, 확인을 지나치면 받아둔 MP3·MP4가 사라진다. 다시 받을 수는 있지만 시간이 든다.
- 자막 없는 레코드가 생기면서 작업 페이지의 자막 영역, 자막 내려받기 경로, 자막 아이콘이 모두 "없음"을 제대로 다뤄야 한다. 한 군데라도 빠지면 빈 화면이나 오류가 날 수 있다. 수용 기준에 자막 없는 경로를 명시해 검증한다.
- `data/records.json` 하나에 목록·메모·자막을 모두 담는 현재 구조에서 메모 저장과 다른 쓰기(등록·삭제)가 겹치면 경합이 날 수 있다. 로컬 단일 사용자라 확률은 낮다.
